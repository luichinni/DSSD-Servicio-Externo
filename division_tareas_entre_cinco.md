## Reglas de oro del equipo para no bloquearse

1. **Desacoplar la Base de Datos:** Nadie debe esperar a que la BD esté subida a la nube para empezar a programar. Todos deben usar una cadena de conexión a un PostgreSQL local (o un contenedor de Docker local) durante los primeros días de desarrollo. Solo se cambian las variables de entorno al probar en la nube.
2. **Desacoplar la Autenticación:** Mientras el **Dev 1** desarrolla el Middleware JWT, los **Dev 3, 4 y 5** deben crear sus endpoints de forma pública o comentando temporalmente el decorador de seguridad (ej. `@jwt_required`). La seguridad se "enciende" directamente en la etapa de integración final.
3. **Desarrollo Orientado a Contratos:** Al tener definidos los JSON en el documento de especificaciones, los desarrolladores del Core (Dev 4 y 5) saben exactamente qué reciben y qué devuelven de los endpoints. No necesitan que la aplicación web ni Bonita estén terminados para usar herramientas como Postman e inyectar esos JSON a sus rutas locales para probar la lógica de base de datos.
